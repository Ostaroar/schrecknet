# ADR 0010 — Argon2 for game-group write passphrases

## Status

Accepted.

## Context

A game-group share code originally granted both read and write access. Groups
need optional write protection without introducing accounts. Storing plaintext
passphrases or fast general-purpose hashes would make a leaked `app.sqlite`
needlessly dangerous.

## Decision

Use the Rust `argon2` crate on the server. Each protected group stores only an
Argon2id PHC string with a fresh 128-bit salt generated by SQLite
`randomblob(16)`. The share code remains the read capability. Log, update, and
delete operations verify the optional write passphrase server-side. Existing
groups have a NULL hash and remain writable for backward compatibility.

Passphrases are sent only with mutation requests and are kept in browser
session storage, not persistent local storage.

## Alternatives considered

- Plaintext storage: rejected because a database leak would expose every
  passphrase directly.
- SHA-256 or another fast hash: rejected because offline guessing would be
  cheap.
- Browser-only checks: rejected because callers could bypass the UI through
  REST or MCP.
- Accounts and password reset: deferred; they add identity, email, and recovery
  infrastructure far beyond the private-group use case.

## Consequences

`argon2` is a new server runtime dependency. Group creation and protected writes
perform intentionally expensive password hashing or verification. A forgotten
passphrase cannot be recovered; a future administrator workflow may replace a
hash, but the application cannot reveal the original secret.
